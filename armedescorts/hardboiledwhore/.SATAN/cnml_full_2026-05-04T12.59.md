# CNML Specification v0.10

## 0. Overview

CNML (Cognitive Narrative Markup Language) is a strictly well-formed XML-based language for representing narrative structure, communicative acts, and expressive delivery.

It models:

* **What is happening** → via acts
* **How it is expressed** → via modifiers
* **Where it applies** → via tree structure

---

## 1. Structural Rules

### 1.1 XML Compliance

CNML documents MUST be:

* Well-formed XML
* Properly nested
* Fully closed (except self-closing tags)

---

### 1.2 Containment

* All elements MUST be fully contained within their parent.
* No element may cross another element’s boundary.

---

## 2. Element Classes

---

### 2.1 Acts (Inline-Block Containers)

Acts define **communicative frames**.

Examples:

* `<say>` — verbal expression
* `<think>` — cognition
* `<feel>` — affective state
* `<gesture>` — physical action
* `<shout>` — intensified verbal act (optional but recommended)

#### Properties

* Acts are inline-block elements
* Acts may appear within inline flow
* Acts may contain:

  * text
  * modifiers
  * other acts
* Acts may nest

---

### 2.2 Modifiers (Inline Span Elements)

Modifiers define **expressive conditions over spans**.

Examples:

* `<quiet>`
* `<loud>`
* `<calm>`
* `<emph>`
* `<gentle>`
* `<smooth>`
* `<nonverbal>`

#### Properties

* Modifiers apply to the content within their subtree
* Modifiers may contain:

  * text
  * acts
  * other modifiers
* Modifiers may nest arbitrarily

---

## 3. Interpretation Model

---

### 3.1 Local Semantics

> **Meaning is determined by containment.**

* Each element applies only to its subtree
* No element has effects outside its structural scope
* No implicit propagation or inheritance beyond containment

---

### 3.2 Acts Define Frames

Acts establish a communicative context:

```
<say>...</say>
```

All enclosed content is interpreted as occurring within that act,
unless overridden by a nested act.

---

### 3.3 Modifiers Define Expressive Fields

> Modifiers define **expressive conditions over regions of the tree**

* A modifier applies uniformly to all content within its subtree
* This includes text, acts, and mixed content

---

### 3.4 Continuous Expressive Fields

When a modifier encloses multiple elements:

```
<quiet>
  <say>...</say>
  <gesture>...</gesture>
</quiet>
```

it defines a **continuous expressive field** across them.

This represents:

* temporal continuity
* shared delivery context
* unified expressive state

---

### 3.5 Nested Composition

Modifiers compose via nesting:

```
<quiet>
  <emph>word</emph>
</quiet>
```

Interpretation:

* quiet baseline
* local emphasis override

---

### 3.6 Override Rule

```
Inner modifiers override outer modifiers on overlapping spans.
```

---

### 3.7 No Act-Level Semantics

> There is no distinction between “modifying an act” and “modifying its content”.

```
<quiet><say>text</say></quiet>
≡
<say><quiet>text</quiet></say>
```

when the modifier fully covers the act’s content.

---

## 4. Granularity Model

```
Prosody is a property of spans, not of acts.
```

Implications:

* A single act may contain heterogeneous delivery
* Fine-grained variation is supported
* No requirement for uniform tone within an act

---

## 5. Modal Composition

Modifiers are **modality-agnostic**.

They apply equally to:

* speech (`<say>`)
* gesture (`<gesture>`)
* thought (`<think>`)
* affect (`<feel>`)

---

## 6. Usage Patterns

---

### 6.1 Local Modification

```
<say><quiet>text</quiet></say>
```

---

### 6.2 Continuous Field

```
<quiet>
  <say>…</say>
  <gesture>…</gesture>
</quiet>
```

---

### 6.3 Degenerate Form

```
<quiet><say>…</say></quiet>
```

* Valid
* Semantically equivalent to internal placement
* Discouraged for clarity unless grouping is intended

---

## 7. Design Principles

* Acts define **what is happening**
* Modifiers define **how it is realized**
* Meaning is determined by **structure, not order**
* Expressive conditions are **region-based**
* Interpretation is **strictly local and hierarchical**

---

## 8. RELAX NG Schema (Compact Syntax)

```rnc
namespace cnml = ""

start = content*

content =
    text
  | act
  | modifier

# ======================
# Acts
# ======================

act =
    say
  | think
  | feel
  | gesture
  | shout

say = element say { content* }
think = element think { content* }
feel = element feel { content* }
gesture = element gesture { content* }
shout = element shout { content* }

# ======================
# Modifiers
# ======================

modifier =
    quiet
  | loud
  | calm
  | emph
  | gentle
  | smooth
  | nonverbal

quiet = element quiet { content* }
loud = element loud { content* }
calm = element calm { content* }
emph = element emph { content* }
gentle = element gentle { content* }
smooth = element smooth { content* }
nonverbal = element nonverbal { content* }

# ======================
# Text
# ======================

text = text
```

## 11. Summary

CNML is a **tree-based expressive markup system** where:

* Acts structure narrative events
* Modifiers define expressive conditions
* Meaning arises entirely from containment

No global state, no cross-boundary effects, no hidden inheritance.
