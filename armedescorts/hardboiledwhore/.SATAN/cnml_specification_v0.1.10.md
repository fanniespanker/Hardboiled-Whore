# CNML Specification v0.1.10

## Foundations

CNML is a constrained XML vocabulary with semantic rules. All CNML documents MUST be well-formed XML.

## Narrative Ontology

- `<narrative>` is not objective reality.
- It is a *projection generated by a narrator model*.
- The narrator may be unreliable, dishonest, delusional, hallucinating, or subject to misremembering.
- All CNML discourse is interpreted relative to this potentially unreliable narratorial projection.

## Discourse

- Default mode: implicit `<narrative>`
- Narrative is the primary container for all discourse, including internal, non-actualized, and temporal variants.

- Narrative modalities (`<fantasy>`, `<dream>`, `<flashback>`, `<remember>`) are structurally distinct but semantically unified with internal cognitive operators such as `<feel>`.
  - These modalities behave as *internal state projections of the main character or focal subject into narrative space*.
  - They are functionally analogous to cognitive operators like `<feel>`, in that they do not represent external objective events, but internal or reconstructed experiential states rendered into discourse form.
  - Despite differing semantic labels, they share a common role as subjective projection layers within `<narrative>`.

## Discourse Units

- Derived from blank-line separation
- Computed per container

## Expression Modality

- `<say>`: spoken utterance
- `<shout>`: high-intensity spoken utterance
- `<think>`: internal verbal cognition, representational thought, or self-directed propositional language
- `<feel>`: low-level cognition / autonomic and limbic state (instinct, hunger, arousal, discomfort, etc.)
  - Replaces prior `<think mode="instinct">`
- `<gesture>`: nonverbal embodied action

## Prosody

Prosody is a multidimensional semantic modulation system applied across CNML inline elements.

Each dimension is bipolar and compositional:

- `<quiet>` ←→ `<loud>`
- `<calm>` ←→ `<excited>`
- `<gentle>` ←→ `<forceful>`
- `<smooth>` ←→ `<harsh>`
- `<engaged>` ←→ `<detached>`
- `<emph>` ←→ `<deemph>`

### Semantics

- Prosodic dimensions may be stacked and combined
- They apply across both spoken and internal modalities
- They do not alter discourse structure, only expression quality
- Prosody tag ordering is interpreted as natural language sequencing and is therefore semantically ambiguous and context-dependent
- `<nonverbal>` is a prosodic tag indicating embodied or non-lexical expression emphasis

## Integrity

- `<redacted>`, `<censored>`, `<glitched>`

## Music DSL

Music DSL is a structured, human-readable temporal annotation layer for expressive or performative text segments.

Music elements may appear as semantic content inside ANY CNML container.

### Core Element

```xml
<music time="" beat="" key="" mode="" tempo="" mood="">
```

### Attributes

- `time`: bar or measure index (optional, qualitative or numeric)
- `beat`: meter unit or grouping
- `key`: tonal center (A–G with optional octave/accidentals in content layer)
- `mode`: modal context (major, minor, lydian, etc.)
- `tempo`: expressive tempo descriptor (non-metronomic allowed)
- `mood`: descriptive or desired emotional outcome

### Music DSL Grammar

The Music DSL content model is line-oriented and token-based.

#### Top-level structure

```
<music> ::= "<music" attributes ">" content "</music>"

attributes ::= (time | beat | key | mode | tempo | mood)*
```

#### Content model

```
content ::= bar ("|" bar)*

bar ::= sequence

sequence ::= element (whitespace element)*
```

#### Element types

```
element ::= note | rest | tie | comment | text
```

#### Note syntax

```
note ::= pitch ":" duration "{" lyric "}" | pitch ":" duration | pitch "{" lyric "}" | pitch

pitch ::= [A-G] accidental? octave?
accidental ::= "#" | "b"
octave ::= [0-9]
```

#### Duration

```
duration ::= [0-9]+ "/" [0-9]+   // e.g. 1/4, 3/16
```

#### Rest

```
rest ::= "R" (":" duration)?
```

#### Tie / sustain

```
tie ::= "~"
```

- Ties connect preceding and following notes or sustain state across elements.

#### Comments

```
comment ::= "//" any_text_to_end_of_line
```

#### Text / ellipsis

```
text ::= "..." | raw_tokens
```

### Semantics

- Music DSL is non-binding and does not enforce timing
- It represents structured performance intuition over text
- Lyrics in `{}` bind phonetic/semantic alignment to musical events
- Missing octave/duration implies context-dependent interpretation
- Ties (~) indicate sustained or blended musical state
- Bars (`|`) segment temporal grouping

### Composition Rules

- Music elements may be nested inside any CNML container
- Multiple `<music>` tags may exist per discourse unit
- Music does not override discourse or prosody semantics

## Nesting Rules

- Nesting of discourse elements is permitted (`<say>`, `<think>`, `<feel>`, `<dream>`, `<fantasy>`, `<flashback>`, `<remember>`, `<shout>`, `<gesture>`, etc.)
- Individual authors may impose stricter structural constraints, but the CNML specification does not enforce a global nesting restriction.
- Overlapping or recursive narrative cognition structures are valid CNML.

## Rules

- All CNML documents MUST be well-formed XML
- Inline elements compose
- No cross-boundary inheritance
